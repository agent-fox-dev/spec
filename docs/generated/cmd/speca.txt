Command speca reports the state of a version 3 specification package, moves the
state of its tasks, moves the package through its lifecycle, converts a version
2 package to version 3, and runs the package's gate.

    speca [flags] <spec>
    speca <spec> --validate
    speca --list [--all]
    speca --next
    speca <spec> --task T --state S [--force] [--dry-run]
    speca <spec> --status S [--by <spec>] [--force] [--dry-run]
    speca <spec> --render [--dry-run]
    speca --render [--all] [--dry-run]
    speca <spec> --migrate [--dry-run]
    speca --migrate [--all] [--dry-run]
    speca <spec> --gate task|full [--base <commit>] [--clean-env] [--timeout <duration>]
    speca <spec> --gate-report [--since <commit>]

It takes one input, a reference to a spec package, and writes exactly one JSON
object to stdout: the package's state, its verdict under --validate, with
--list and no input, every package under the spec root, with --next the package
to implement now, or, in the task and status forms, the package's state after
the change and the changes made, under --render what it did to the package's
spec.md, and under --migrate what it did to the package's format version. The
report, --validate, --list and --next read the packages and change nothing: they
write no file. The task form writes progress.json and no other file. The status
form writes the package through the library, which rewrites every artifact of it
and its spec.md, and moves an archived or superseded package under archive/. The
render form writes spec.md, the package's render, and no other file. The migrate
form rewrites a version 2 package as version 3 and removes its test_spec.json.
The gate form runs the package's linter and all_tests commands and the gate
report sums the gates that ran; neither writes under --dir, and what the gate
keeps (the commands' logs, the passes it reuses, the run log) goes to the user's
state directory. No form makes a model or network call or reads a credential.
Its siblings are spec, which writes a package from an idea, and specr, which
renders one as Markdown.

FUNCTIONS

func Main(argv []string, stdout, stderr io.Writer) int
    Main parses argv, reports, and writes one envelope to stdout. It returns the
    exit code.

    Two paths are for a person and print text instead: --version, and -h/--help
    or a bare invocation, which print the help to stderr. A bare invocation also
    writes a usage envelope when stdout is not a terminal, so a program piping
    stdout still gets one object to parse.


TYPES

type Result struct {
	envelope.AdminResult

	// Has unexported fields.
}
    Result is speca's result. Its fields are the envelope package's AdminResult,
    which a program reading the output decodes into; the methods are what the
    shell asks of a result.

func (r *Result) Next() []cli.Next
    Next suggests only calls that exist: rendering the task to work on with
    specr. The verdict, the gate and the gate report suggest none, and neither
    does a report or a list that has no task to name.

func (r *Result) Resumable() bool
    Resumable says whether running the call again continues the work. The shell
    asks the result, and reports it in the error.

func (r *Result) Summary() string
    Summary is the envelope's one sentence. The fields a form fills say
    which form it was: packages for the list, validation for the verdict,
    and otherwise it is the report.
