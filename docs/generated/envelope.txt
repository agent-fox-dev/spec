package envelope // import "github.com/agent-fox-dev/spec/envelope"

Package envelope defines the JSON that the spec, specr and speca commands write
to stdout, as Go types a program can decode it into.

Every command writes exactly one JSON object on every program-driven path,
including the failing ones: an Envelope. Its result property holds the command's
own result, and which type that is depends on the command:

    spec   a SpecResult    the package(s) a run wrote
    specr  a RenderResult  a package rendered as Markdown
    speca  an AdminResult  a package's state, its verdict, the list of packages, or a change to its tasks

Decode a command's output with the function for its result:

    env, err := envelope.DecodeSpecr(stdout)
    if err != nil {
    	return err // not an envelope at all
    }
    if !env.OK {
    	return env.Error // an *ErrorInfo: stage, category, message, fix hint
    }
    md := env.Result.Markdown

Decode is the same for any other result type, and Envelope[any] reads a result
of a shape the caller does not know.

The package depends on the standard library only, so importing it pulls in
neither the commands' machinery nor a model SDK. The commands themselves build
their output from these types, so the two cannot drift apart: a field added to
the output is a field added here.

# Compatibility

The types follow the commands' output. Fields are added over time and a decoder
ignores the ones it does not know; a field's name and meaning do not change.
Code, category and stage names are open sets: a value this package has no
constant for is not an error.

    on one package, the verdict on one package (--validate), the list of every
    package (--list), the render form (--render), the migrate form (--migrate)
    and the task and status forms, which are the report on the package after
    a change, with the changes they made. A form fills the fields it produces
    and the rest are absent: Valid is a pointer so that false is written,
    and the slices that must show as [] in their own form are omitted when nil
    rather than empty.

type Artifact struct {
	Kind ArtifactKind
	// spec_package, markdown_file
	Path  string
	ID    string
	Valid bool
	// comment
	URL  string
	Role string
	// DryRun marks an entry as hypothetical: it would have been written but
	// for --dry-run.
	DryRun bool
}
    Artifact is one thing a run produced. Only the fields of its own Kind are
    written, and only those are read back, so a caller never has to know which
    fields to ignore.

func (a Artifact) MarshalJSON() ([]byte, error)
    MarshalJSON writes exactly the fields fixed for a's own Kind.

func (a *Artifact) UnmarshalJSON(data []byte) error
    UnmarshalJSON reads what MarshalJSON writes.

type ArtifactKind string
    ArtifactKind is the closed set of shapes an Artifact can take.

const (
	ArtifactSpecPackage  ArtifactKind = "spec_package"
	ArtifactComment      ArtifactKind = "comment"
	ArtifactMarkdownFile ArtifactKind = "markdown_file"
)
    The artifact kinds the commands produce.

type Change struct {
	Kind   string `json:"kind,omitempty" description:"what changed: task (the state of a task), status (the package's lifecycle status), supersedes (an id added to the supersedes list of the replacing package) or moved (the package's directory); the set is open"`
	ID     int    `json:"id,omitempty" description:"task: the id of the task that changed"`
	From   string `json:"from,omitempty" description:"task: the state it was in (pending, in_progress, done or dropped); status: the status it was in; moved: the directory it was in"`
	To     string `json:"to,omitempty" description:"task: the state it was set to; status: the status it was set to; moved: the directory it was moved to"`
	Forced bool   `json:"forced,omitempty" description:"task: true when --force set a state the task state machine would have refused; absent otherwise"`
	Spec   string `json:"spec,omitempty" description:"supersedes: the spec_id of the replacing package, whose supersedes list was changed"`
	Added  string `json:"added,omitempty" description:"supersedes: the spec_id that was added to that list, the package that was superseded"`
}
    Change is one change a call made to a package, or under --dry-run would have
    made. The set of kinds is open. speca's task form writes the kind task.
    Its status form writes status (the package's lifecycle status, from and to),
    supersedes (the replacing package's spec, and the id added to its supersedes
    list) and moved (the package's directory, from and to), in the order it made
    them.

type Envelope[R any] struct {
	Tool     string `json:"tool" description:"the command that wrote this envelope"`
	Version  string `json:"version" description:"the command's build identity"`
	OK       bool   `json:"ok" description:"true only when the command did the whole job it was asked to do; never true beside a non-zero exit_code or an error"`
	Status   string `json:"status" description:"the outcome in words, derived from exit_code: done (0), failed (1) or usage (2)"`
	ExitCode int    `json:"exit_code" description:"the process exit code: 0 done, 1 failed, 2 usage error"`
	Summary  string `json:"summary" description:"one sentence on the outcome, at most 200 characters"`

	Error       *ErrorInfo   `json:"error,omitempty" description:"what failed and where; present exactly when ok is false"`
	Warnings    []Warning    `json:"warnings,omitempty" description:"what went differently than intended without stopping the run"`
	Result      R            `json:"result,omitzero" description:"the command's own result"`
	Artifacts   []Artifact   `json:"artifacts,omitempty" description:"what the run produced, read off facts the command holds"`
	SideEffects []SideEffect `json:"side_effects,omitempty" description:"every write to a forge, in the order it happened"`
	Next        []Next       `json:"next,omitempty" description:"the invocations a caller would plausibly make next"`

	Input *InputInfo `json:"input,omitempty" description:"what the one positional argument turned out to be"`
	Model *ModelInfo `json:"model,omitempty" description:"the models the run used"`
	Usage *UsageInfo `json:"usage,omitempty" description:"the run's model cost, summed over every phase"`

	DurationMS int64  `json:"duration_ms" description:"wall-clock time of the run, in milliseconds"`
	StartedAt  string `json:"started_at" description:"when the run started, RFC 3339 in UTC"`
}
    Envelope is the single JSON object a command writes to stdout. R is the
    type of the command's own result: SpecResult for spec, RenderResult for
    specr, AdminResult for speca. Use a pointer type, as SpecEnvelope and
    RenderEnvelope do, to tell an absent result from an empty one; a failure
    that happened before there was anything to report has none.

func Decode[R any](data []byte) (Envelope[R], error)
    Decode reads the envelope a command wrote. It fails when data is not one
    JSON object, or when a field has the wrong type; unknown fields are ignored.
    A command writes exactly one object, so data after it is an error too.

type ErrorInfo struct {
	// Stage is the pipeline step that failed: usage, input, preflight, prd,
	// requirements, tasks, plan, scaffold, write, validate, budget,
	// load; and, for speca's task and status forms, status (the package cannot
	// take a write, or the lifecycle does not allow the move), task (the state
	// machine refuses a move) and archive (the package cannot be moved under
	// archive/).
	Stage string `json:"stage" description:"the step that failed"`
	// Category says whether re-running could help.
	Category  string   `json:"category" description:"the kind of failure, which says whether re-running could help; an open set"`
	Message   string   `json:"message" description:"what failed, in words"`
	Retryable bool     `json:"retryable" description:"whether re-running the identical command could succeed"`
	Resumable bool     `json:"resumable" description:"whether re-running the same input continues the work rather than starting it over"`
	FixHint   *FixHint `json:"fix_hint,omitempty" description:"a mechanical remedy, where one is known"`
	// Has unexported fields.
}
    ErrorInfo says what failed and where. It is present exactly when ok is
    false. It is an error, so a caller can return it as it is.

type OpenQuestion struct {
	Question string `json:"question"`
	Decision string `json:"decision"`
	Why      string `json:"why_unsure"`
}
    OpenQuestion is one decision made under uncertainty.

    It is the shape the "self-resolve, flag low confidence" contract takes:
    the question was answered, the answer is in the PRD, and this records that
    a different answer would have produced different work. A caller that wants
    a human in the loop reads this array; a caller that does not still gets a
    finished spec.

type Package struct {
	// SpecDir is the created package, relative to the repository root when
	// it is inside it.
	SpecDir  string `json:"spec_dir"`
	SpecID   string `json:"spec_id"`
	SpecName string `json:"spec_name"`
	Title    string `json:"title"`
	Status   string `json:"status"`
	Source   string `json:"source"`
	// Artifacts are the files written, in the order they were produced.
	Artifacts []string `json:"artifacts"`

	// Counts summarize the package without reproducing it. A caller that
	// wants the content reads the files.
	Requirements   int `json:"requirements"`
	Criteria       int `json:"criteria"`
	ExecutionPaths int `json:"execution_paths"`
	// Tasks counts the tasks of tasks.json; the integration task, which is
	// derived, is not among them.
	Tasks int `json:"tasks"`

	// Validation is the format's own verdict on the package.
	Validation ValidationReport `json:"validation"`
	// Traceability is derived from the checks and task.criteria, never
	// stored — the format makes both computed, so reporting them here is the
	// only place they exist.
	Traceability TraceReport `json:"traceability"`

	// OpenQuestions are the decisions the PRD phase made under uncertainty
	// and would like a person to check. An empty list means the input and
	// the codebase settled everything.
	OpenQuestions []OpenQuestion `json:"open_questions,omitempty"`

	// CommentURL is set when the finished PRD was posted back to the issue.
	CommentURL string `json:"comment_url,omitempty"`

	// RelevantFiles are the files the PRD phase identified as important for
	// later generation phases. They live only in the envelope and the
	// run-time pipeline, never inside the spec package directory.
	RelevantFiles []RelevantFile `json:"relevant_files,omitempty"`

	// Review is how the PRD was reviewed and revised before the package was
	// generated from it. It is present exactly when the run had
	// --adversarial on.
	Review *Review `json:"review,omitempty"`
	// PlanReview is how the plan was reviewed and revised before the package
	// was written, with --adversarial-plan; absent without it.
	PlanReview *Review `json:"plan_review,omitempty"`

	// Detail records which view of this result was emitted: "summary" or
	// "full". It is present on both.
	Detail string `json:"detail"`
}
    Package describes one specification package.

func (p *Package) SetDetail(d string)

type Review struct {
	// RoundsRun counts the rounds started, a review with no findings
	// included. It is 0 when the budget stopped the run before the first
	// review.
	RoundsRun int `json:"rounds_run"`
	// RoundsAllowed is the round limit, --adversarial-rounds or 1.
	RoundsAllowed int `json:"rounds_allowed"`
	// StopReason is the one reason the rounds stopped: one of the three
	// ReviewStop constants.
	StopReason string `json:"stop_reason"`
	// The totals over every round, derived from the rounds. FindingsCount is
	// the sum of the other five.
	FindingsCount   int `json:"findings_count"`
	FixedCount      int `json:"fixed_count"`
	ContestedCount  int `json:"contested_count"`
	EscalatedCount  int `json:"escalated_count"`
	DeclinedCount   int `json:"declined_count"`
	UnansweredCount int `json:"unanswered_count"`
	// Rounds are the rounds in order. The --detail summary view leaves them
	// out and keeps the counts.
	Rounds []ReviewRound `json:"rounds,omitempty"`
}
    Review is the adversarial review of one package's PRD: every round, every
    finding, and what became of it. It lives only in the result, never in the
    package directory.

type ReviewFinding struct {
	// ID is R<round>-F<n>, assigned by the run in the order the reviewer
	// submitted the findings.
	ID       string `json:"id"`
	Severity string `json:"severity"`
	// Rubric is the standard the finding applies: one of the Rubric
	// constants. The reviewer sets it and the reviser cannot change it.
	Rubric   string `json:"rubric"`
	Section  string `json:"section"`
	Flaw     string `json:"flaw"`
	Evidence string `json:"evidence"`
	Remedy   string `json:"remedy"`
	// Reopens is the id of an earlier contested finding this one raises
	// again with evidence the contest did not answer.
	Reopens string `json:"reopens,omitempty"`
	// Disposition is the reviser's answer: one of the Disposition constants.
	// The fields below are the ones that answer carries, and absent for the
	// others.
	Disposition string `json:"disposition"`
	// Reason is why a contested finding does not hold, why a declined one is
	// not remedied in this package, or why an escalation's decision is
	// uncertain.
	Reason string `json:"reason,omitempty"`
	// CounterEvidence is a contest's: a quote found in the PRD or the input,
	// or a repository path that exists, with what it shows.
	CounterEvidence string `json:"counter_evidence,omitempty"`
	// Question, Options and Decision are an escalation's: the question a
	// person should answer, the two or three options, and the one the reviser
	// took provisionally.
	Question string   `json:"question,omitempty"`
	Options  []string `json:"options,omitempty"`
	Decision string   `json:"decision,omitempty"`
}
    ReviewFinding is one flaw a reviewer reported and what became of it.

type SpecResult struct {
	Package

	// FollowOnSpecs are the further packages this run wrote, in order, when
	// the input was more than one spec's worth of work.
	FollowOnSpecs []Package `json:"follow_on_specs,omitempty"`
	// Split is every scope of the split with its state: done, invalid,
	// failed or pending. Empty when the input was one spec's worth of work.
	Split []ScopeReport `json:"split,omitempty"`
	// SplitPlan is the plan file left in the spec root while the split is
	// unfinished. Running spec on the same input again resumes from it.
	SplitPlan string `json:"split_plan,omitempty"`
	// Stage is "preflight" on a --preflight run, which stops before any
	// model phase; it is absent on an ordinary run.
	Stage string `json:"stage,omitempty"`
	// DryRun records that nothing was written.
	DryRun bool `json:"dry_run,omitempty"`
	// Preflight and Estimate are set only by a --preflight run whose checks
	// all passed: the checks that were performed, and what the real run would
	// spend at most.
	Preflight []PreflightCheck `json:"preflight,omitempty"`
	Estimate  *Estimate        `json:"estimate,omitempty"`
}
    SpecResult is the result of the spec command: the package a run wrote,
    and for an input that was more than one spec's worth of work, the further
    packages and the whole plan.

    The fields of the first package this run wrote sit at the top level,
    so a run on an input that is one spec's worth of work reports exactly that
    package. Under --detail summary only some of the fields are written (the
    ones a caller acts on next); Detail says which view this is.
